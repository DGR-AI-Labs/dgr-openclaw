# Feedback and triage

Use [GitHub Discussions](https://github.com/DGR-AI-Labs/dgr-openclaw/discussions) for questions, successful setup reports and workflow ideas. Use [GitHub Issues](https://github.com/DGR-AI-Labs/dgr-openclaw/issues/new/choose) for bug reports, documentation corrections and concrete use-case proposals. Include the tested commit or release, OS and OpenClaw version. A GitHub account is required.

Report suspected vulnerabilities through [private vulnerability reporting](https://github.com/DGR-AI-Labs/dgr-openclaw/security/advisories/new). Never include credentials or personal data in public reports.

Maintainers apply one status label at a time: `status:triage` for new reports, `status:investigating` while assessing, `status:accepted` for agreed work, and `status:resolved` when addressed. Close resolved issues with the outcome and relevant fix or explanation. These labels are manually maintained; there is no automatic response-time promise. A proposal being accepted does not approve implementation scope or release.

ClawHub users should be directed to these same discussion and issue entry points. Feedback received elsewhere can be summarized here manually with permission and without personal information; there is no automatic ClawHub import.

Contributors disclose actual authorship and tests performed. New use cases follow the contribution and review requirements of the implementation; they do not gain release approval by opening an issue.
